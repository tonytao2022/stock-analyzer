## 1. 概述

### 1.1 解决的问题

7/15持仓全线崩溃暴露的核心产品缺陷：**系统没有机制说"我可能错了"**。

- 持仓评分5.0 → 仍输出HOLD信号（无信号与评分的一致性校验）
- 持仓-37%浮亏 → 系统输出"持有关注"（无亏损容忍度检查）
- 评分与信号矛盾 → 用户承担信息不一致的认知负担

### 1.2 解决方案架构

```
评分引擎 → system_confidence(per-stock) → 信号一致性校验(3项检查) → 最终输出(信号+置信度标签)
              ↑                                    ↑
         4因子等权计算                       逐项检查，不通过加标注
```

## 2. system_confidence 字段定义

### 2.1 基本信息

| 属性 | 值 |
|:----|:----|
| 字段名 | `system_confidence` |
| 类型 | float |
| 范围 | 0.0 ~ 1.0 |
| 粒度 | **per-stock**（每只持仓股票独立计算） |
| 刷新时机 | 每次评分管道完成后刷新（当前：17:00收盘评分管道） |
| 输出位置 | `portfolio_holdings` 表新增字段 + API返回字段 |

### 2.2 计算公式（等权 4因子 × 25%）

```
system_confidence = 
    w1 × season_confidence        (25%)
  + w2 × score_stability          (25%)
  + w3 × penalty_health           (25%)
  + w4 × sector_signal_agreement  (25%)
```

### 2.3 因子明细

#### 因子1: season_confidence（季节置信度）

| 输入 | 说明 | 来源 |
|:----|:----|:-----|
| 当前季节判定 | season_state表最新记录 | 后端已有 |
| 季节置信度 | 0.0~1.0 | season_state表已有 |

**计算规则**: 直接使用季节判定的置信度。

| 场景 | 值 | 含义 |
|:----|:--:|:-----|
| 置信度≥80% | 0.8~1.0 | 季节判断可信 |
| 60%~80% | 0.6~0.8 | 季节判断较模糊 |
| <60% | 0.0~0.6 | 季节判断不可靠 |

#### 因子2: score_stability（评分与近期均值偏差）

| 输入 | 说明 | 来源 |
|:----|:----|:-----|
| 当前评分 | buy_score | strategy_signal_daily |
| 近30日均分 | 30日移动均值 | 由历史评分表计算 |
| 近5日均分 | 5日移动均值 | 由历史评分表计算 |

**计算规则**:
```
deviation = abs(当前评分 - 近30日均分) / 近30日均分
score_stability = max(0, 1 - deviation)
```

| 场景 | deviation | score_stability | 含义 |
|:----|:---------:|:---------------:|:-----|
| 评分稳定 (±5%) | ≤0.05 | ≥0.95 | 评分可信 |
| 评分波动 (±20%) | 0.20 | 0.80 | 评分需谨慎 |
| 评分剧变 (>40%) | >0.40 | <0.60 | 评分异常，需人工复核 |

#### 因子3: penalty_health（惩罚分总和的健康度）

| 输入 | 说明 | 来源 |
|:----|:----|:-----|
| 惩罚分总和 | 引擎输出的penalty_sum | p6_dual_track_engine |
| 惩罚分上限 | 引擎定义的惩罚上限 | 引擎配置 |

**计算规则**:
```
penalty_ratio = penalty_sum / penalty_max
penalty_health = max(0, 1 - penalty_ratio)
```

| 场景 | penalty_ratio | penalty_health | 含义 |
|:----|:------------:|:--------------:|:-----|
| 几乎无惩罚 | 0~0.2 | 0.8~1.0 | 评分自然形成 |
| 中等惩罚 | 0.2~0.5 | 0.5~0.8 | 有一定修正压力 |
| 高惩罚 | >0.5 | <0.5 | 评分被大幅压制，不可靠 |

> **注意**: 如果引擎当前不输出penalty_sum字段，可先临时用 `max(0, 1 - 惩罚触发次数/最大惩罚次数)` 替代。后续由MAY落地惩罚分总和字段。

#### 因子4: sector_signal_agreement（行业信号一致性）

| 输入 | 说明 | 来源 |
|:----|:----|:-----|
| 该股票所在行业 | sector | stock_basic |
| 同行业所有持仓的信号分布 | 信号状态汇总 | strategy_signal |
| 该股票的信号 | 当前信号 | strategy_signal |

**计算规则**:
```
同行业其他持仓中，与本股票信号方向一致的占比 = agreement
sector_signal_agreement = agreement
```

| 场景 | agreement | 含义 |
|:----|:---------:|:-----|
| 行业信号一致（>80%同向） | >0.8 | 行业趋势明确，信号可信 |
| 行业信号分歧（50%~80%） | 0.5~0.8 | 行业内有分化，需关注个股 |
| 行业信号混乱（<50%） | <0.5 | 行业无明确趋势，个股信号不可靠 |

### 2.4 时序衰减平滑（消除日间噪声）

为避免置信度日间剧烈跳变让用户困惑，置信度输出前做**加权平滑**：

```
display_confidence = raw_today × 50% + yesterday × 30% + day_before × 20%
```

| 使用场景 | 说明 |
|:---------|:-----|
| 数据库写入 | 写平滑后的display_confidence，不写raw值 |
| API返回 | 返回display_confidence + 附加raw_today |
| 前端展示 | 展示display_confidence + 趋势箭头 |

**趋势箭头规则**（基于raw_today与display_confidence的差值判断）：

| 条件 | 箭头 | 含义 |
|:----|:----:|:-----|
| raw_today - display_confidence > +0.10 | ↑ 快速上升 | 评分正在改善 |
| raw_today - display_confidence < -0.10 | ↓ 快速下降 | 评分在恶化（即使平滑后看着还行）|
| 差值在±0.10以内 | → 平稳 | 置信度稳定 |

> **目的**：用户看到的是

| system_confidence | 等级 | 标签 | 显示颜色 | 含义 |
|:----------------:|:----:|:----:|:-------:|:-----|
| ≥0.8 | 🟢 高 | 高置信度 | 绿色 | 评分可信，可按信号操作 |
| 0.5~0.8 | 🟡 中 | 中等置信度 | 黄色 | 评分需关注，适当减仓 |
| 0.3~0.5 | 🟠 低 | 低置信度 | 橙色 | 评分不可靠，加强监控 |
| <0.3 | 🔴 极低 | ⚠️ 信心不足 | 红色 | 系统判断不可靠，强制输出警示 |

## 3. 信号一致性校验（3项检查）

在每次持仓信号输出前，自动执行3项检查。任一项不通过→不阻断信号输出→但追加标注。

### 检查①: 评分是否仍然支持信号

| 属性 | 值 |
|:----|:----|
| 触发条件 | 持仓信号为BUY/STRONG_BUY/CAUTIOUS_BUY/HOLD，但当前评分 < 买入阈值 |
| 买入阈值源 | system_config表（按季节动态读取） |
| 检查逻辑 | `if signal in [BUY,STRONG_BUY,CAUTIOUS_BUY,HOLD] and current_score < buy_threshold → FAIL` |
| 输出 | 追加标注 "⚠️ 评分已跌破买入线（当前{score}分 < {threshold}分阈值）" |
| 示例 | "⚠️ 评分已跌破买入线（当前5.0分 < 74分阈值）" |

### 检查②: 信号与前日有无根本矛盾

| 属性 | 值 |
|:----|:----|
| 触发条件 | 前日信号为BUY/STRONG_BUY，今日信号为SELL（或反之） |
| 检查逻辑 | `if (prev_signal in [BUY,STRONG_BUY] and curr_signal == SELL) → FAIL` |
| 输出 | 追加标注 "⚠️ 信号反转：昨{prev_signal} → 今{curr_signal}，请复核逻辑" |
| 取消条件 | 同时满足以下条件时不标注（视为合理反转）：<br>1️⃣ 评分变化绝对值 > ±20分<br>2️⃣ **且**评分变化方向与信号变化方向一致（评分上升→信号转买入方向 / 评分下降→信号转卖出方向） |

### 检查③: 亏损是否已超过容忍线

| 属性 | 值 |
|:----|:----|
| 触发条件 | 持仓浮亏百分比 < -15%（硬编码初始值，后续可由Tony在策略参数面板调整）|
| 检查逻辑 | `if profit_pct < -15% → FAIL` |
| 输出 | 追加标注 "⚠️ 亏损超容忍线：当前亏损{profit_pct}%，系统建议仅可卖出操作" |
| 输出色 | 红色加粗 |
| 说明 | 暂不联动风控降级，只输出文本警示 |

## 4. API 与 数据库变更

### 4.1 portfolio_holdings 表新增字段

```sql
ALTER TABLE portfolio_holdings
  ADD COLUMN system_confidence DECIMAL(4,2) DEFAULT NULL COMMENT '系统自我怀疑置信度(0.00~1.00)';
```

### 4.2 portfolio 持仓API返回值变更

现有 `GET /api/v1/management/portfolio/holdings` 返回的 holdings 数组中，每只股票新增：

```json
{
  // ... 现有字段 ...
  "system_confidence": 0.72,
  "confidence_level": "medium",
  "confidence_warnings": [
    "⚠️ 评分已跌破买入线（当前5.0分 < 74分阈值）",
    "⚠️ 亏损超容忍线：当前亏损-34.1%，系统建议仅可卖出操作"
  ]
}
```

### 4.3 新增计算与写入流程

| 步骤 | 执行时机 | 说明 |
|:----|:---------|:-----|
| 1. 评分管道完成 | 每日17:00 | 现有流程 |
| 2. 计算system_confidence | 评分管道完成后 | 后端新增处理 |
| 3. 执行3项检查 | 计算置信度后 | 后端新增处理 |
| 4. 写入portfolio_holdings | 检查完成后 | UPDATE对应记录 |
| 5. 持仓API返回时带出 | 用户访问持仓页面时 | 现有API做字段追加 |
